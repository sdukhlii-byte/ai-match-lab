# AI Match Lab — генератор видео «5 AI-моделей предсказывают счёт»

Матч → реальные прогнозы ChatGPT / Claude / Gemini / Perplexity / Grok →
видео, где рука маркером вписывает счёт в бланк → zip-кит → Telegram-группа →
автопостер `coinplay-predictions-to-social` публикует в Threads, Instagram (Reels) и X.

```
fixtures.py (football-data.org: ближайший реальный матч) ──► матч
            │
            ▼
         stats.py (football-data.co.uk: Elo, форма, H2H — только клубные лиги)
            │
            ▼
         predictions.py (OpenRouter, 5 моделей, веб-поиск + статистика в промпте)
            │
            ▼
         poster.py ──► blank.jpg (пустой бланк на столе)
                   └─► filled.jpg (тот же бланк с цифрами «от руки»)
            │
            ▼
         video.py ──► fal.ai first+last frame ──► рука дописывает цифры
            │          (Kling 2.5 по умолчанию — дешевле; Veo 3.1 как более
            │           дорогая, но фотореалистичная альтернатива со звуком)
            ▼
         ffmpeg: склейка + стоп-кадр 2 сек ──► video.mp4
            │
            ▼
         kit.zip (kit.json + threads/ instagram/ x/) ──► Telegram ──► автопостер
```

Вспомогательный модуль `config.py` разбирает переменные окружения: опечатка
(`SEGMENTS=два`, `HOLD_SEC=2,5`) больше не роняет прогон, а логируется и
заменяется дефолтом.

## Реальная статистика в промпте

Перед запросом к моделям `stats.py` тянет бесплатные CSV с
[football-data.co.uk](https://www.football-data.co.uk) (без ключа, 22 европейские
лиги) и считает по ним:

- **Elo** обеих команд (свой расчёт по всей скачанной истории — CSV не даёт готового рейтинга);
- **форму** за последние 5 матчей (W/D/L, средние голы забитые/пропущенные);
- **личные встречи** (H2H) — сколько раз кто выигрывал, средняя результативность.

Эти цифры добавляются в промпт каждой модели строкой "Real stats: …", моделям
явно сказано ставить свежие новости (травмы, замена тренера) выше исторической
статистики, если они расходятся.

Лига определяется по полю `competition`: сравнение идёт по нормализованному
ключу (регистр, точки, дефисы и диакритика не важны), список — в
`stats.LEAGUE_CODES`. **Не работает** для сборных и турниров без клубного сезона
(Чемпионат мира, товарищеские, Лига чемпионов) и для эсенспорта/UFC — там просто
нет данных на football-data.co.uk, и генератор молча идёт дальше без блока статистики.

Имена клубов, которые в CSV пишутся иначе, чем обычно (`Man City`, `Man United`,
`Ath Madrid`, `Paris SG`), прописаны в `stats.ALIASES` — дополняй по мере
надобности. Если команда не найдена, в лог уходит подсказка с нормализованным
именем и примером того, как клубы называются в CSV.
`USE_STATS=false` — отключить совсем.

## Почему первый + последний кадр

Видео-модель, которой дали только пустой бланк, напишет **свои** цифры: не те,
что предсказали модели, и не те, что в подписи поста. Поэтому последний кадр
рендерится заранее с нашими цифрами, а модель только рисует между кадрами руку
с маркером. В конце ролика на бланке всегда правильный счёт.

## Запуск

```bash
pip install -r requirements.txt          # + ffmpeg в системе
export OPENROUTER_API_KEY=...  FAL_KEY=...
export TELEGRAM_BOT_TOKEN=...  TELEGRAM_CHAT_ID=-100...   # группа, которую читает автопостер

python generate.py --home Spain --away Argentina --home-flag es --away-flag ar \
    --competition "World Cup Final" --date 2026-07-19

python generate.py --match-file matches.json      # пачка матчей
python generate.py --auto                         # сам подберёт ближайшие матчи
```

Полезные флаги:
- `--no-video`: только кадры, промпт и кит с картинкой. Бесплатно, удобно проверить бланк.
- `--scores "1-2,2-1,2-2,1-0,2-1"`: свои счета без запросов к моделям (порядок ChatGPT, Claude, Gemini, Perplexity, Grok).
- `--no-send`: не отправлять в Telegram.
- `--keep-temp`: оставить промежуточные `_seg*.mp4` (по умолчанию удаляются).

Всё складывается в `out/<матч>/`: `blank.jpg`, `filled.jpg`, `prompt.txt`,
`predictions.json`, `video.mp4`, `<матч>.zip`.

Код возврата: `0` — все матчи собраны (или календарь пуст при `--auto`),
`1` — хотя бы один матч не собран. В конце прогона в лог уходит строка «Итог: …».

## Тесты

```bash
pip install -r requirements-dev.txt
python -m pytest -q          # 33 теста, без сети и без ключей
python -m pyflakes *.py
```

Тесты закрывают найденные баги регрессиями: порядок матчей в `stats`, разбор
ответа модели, фильтр статусов в `fixtures`, слаг для нелатинских названий,
детерминизм кадров между сегментами.

### Цена ролика

При `VIDEO_PROVIDER=kling25` (по умолчанию): один сегмент 10 сек ≈ `$0.35` база
+ `$0.07` за каждую доп. секунду ≈ `$0.70`. При `SEGMENTS=2` (рекомендуется для
чистой руки) — это **≈ $1.40 за ролик**, при `SEGMENTS=1` — **≈ $0.70**.

При `VIDEO_PROVIDER=veo31`: `$0.40/сек` (1080p со звуком) × `8` сек ×
`SEGMENTS` — то есть `SEGMENTS=2` даёт уже **≈ $6.4 за ролик**. Используй его
только если важен максимальный реализм и звук маркера, и тогда для экономии
можно снизить `VEO_RESOLUTION=720p` или `VEO_AUDIO=false` (тариф без звука —
`$0.20/сек`, то есть `SEGMENTS=2` ≈ `$3.2`).
| `HOLD_SEC` | `2` | стоп-кадр в конце, чтобы успели прочитать |
| `TABLE_IMAGE` | `assets/table.jpg` | фото столешницы; если файла нет или он битый, рисуется дерево |
| `MUSIC_FILE` / `MUSIC_VOLUME` | — / `0.25` | фоновая музыка и её громкость |
| `ALLOW_PAST_DATES` | `false` | разрешить матчи с прошедшей датой (для тестов) |
| `LOG_LEVEL` | `INFO` | уровень логирования |

## Автоматический подбор реальных матчей (`--auto`)

`Dockerfile` по умолчанию запускает `python generate.py --auto` — генератор сам
находит ближайшие реальные (ещё не сыгранные) матчи топ-лиг через бесплатный API
[football-data.org](https://www.football-data.org):

1. Зарегистрируйся (2 минуты, без карты): https://www.football-data.org/client/register
2. Добавь в переменные Railway: `FOOTBALL_DATA_API_KEY=<ключ из письма>`.
3. Готово — при каждом запуске берутся ближайшие по времени запланированные матчи
   из `FIXTURES_COMPETITIONS` в окне `FIXTURES_DAYS_AHEAD` дней.

Матчи со статусами `SCHEDULED` и `TIMED` считаются одинаково подходящими: у
football-data.org ближайшие игры почти всегда `TIMED`, и фильтр только по
`SCHEDULED` прятал как раз то, что нужно.

Если в окне вообще нет подходящих матчей (пауза в календаре, международное окно,
межсезонье) — это не ошибка: процесс тихо завершается с кодом 0 и предупреждением
в логе, а не падает. Так Railway не уходит в рестарт-луп.

В `FIXTURES_COMPETITIONS` по умолчанию — весь клубный список бесплатного тарифа
football-data.org (9 лиг). Особенно важна **BSA** (бразильская Серия A): у Южной
Америки своё, отдельное от УЕФА международное окно (CONMEBOL), которое почти
никогда не совпадает с европейским — когда все топ-лиги Европы разом встают на
паузу на 10+ дней (например, отборочные к Евро), Бразилейран обычно продолжает
играть, и `--auto` всё равно находит свежий матч.

`matches.json` + `--match-file` никуда не делись — это ручной/тестовый режим.

## Дата матча

Дата обязательно должна быть в будущем (`YYYY-MM-DD`). Прошедшая дата означает,
что у матча уже есть реальный результат — модели этого не знают и просто
нафантазируют правдоподобный «прогноз», поэтому такой матч **отклоняется ещё до
похода к API моделей** (деньги не тратятся).
Отключить проверку: `ALLOW_PAST_DATES=true`.

## Как сделать ближе к референсу

1. **Фото стола.** Сфотографируй свой стол сверху и положи в `assets/table.jpg`.
2. **Иконки моделей.** `assets/icons/chatgpt.png`, `claude.png`, `gemini.png`,
   `perplexity.png`, `grok.png` (PNG с прозрачностью). Если файла нет, рисуется нейтральный значок.
3. **Эмблемы клубов** для клубных матчей: `assets/crests/<club>.png` или URL в
   `home_flag` / `away_flag`. Флаги стран подтягиваются сами по ISO-коду (`es`, `ar`, `gb-eng`).
4. **Длина.** Референс ~17 сек: `SEGMENTS=2` + `HOLD_SEC=2` дают ~18 сек.

## Оформление карточки (бренд Coinplay)

`poster.py` рисует карточку по гайдлайну Coinplay:

- **Цвета**: фон `#09001B`→`#1C0549` (слоистый градиент + мягкие неоновые
  «пузыри»), панели `#2F0B76`/`#51358A`, акцент `#C969FF`, жёлтый `#FFE145`
  (рамка, счётные боксы, «маркер»).
- **Шрифт**: Roboto Condensed (Bold — заголовок, SemiBold — подписи и имена моделей).
- **Лого**: `assets/logo/mark.png`; если файла нет, рисуется приблизительная версия.
- Старые константы (`NAVY`, `LIME`, `CYAN`, `PAPER`) оставлены как алиасы новых цветов.

## Подпись поста

Генерируется из прогнозов: счета всех ответивших моделей, консенсус, самый частый
счёт и призыв «Link in bio». Для X своя версия, гарантированно до 280 символов.

## Деплой (Railway)

`Dockerfile` ставит ffmpeg и cairo, запускает контейнер от непривилегированного
пользователя и не буферизует логи. Сервис работает как cron-job
(`python generate.py --auto`).

## Что было исправлено

**Критично — статистика считалась неправильно**

- `stats._load_matches` разворачивал список дважды (`matches.reverse()` +
  `return list(reversed(matches))`), то есть не делал ничего, и матчи вообще
  никогда не сортировались по дате — сезоны просто склеивались подряд. В итоге
  «форма за последние 5 матчей» брала **первые** матчи сезона, а Elo считался в
  обратном хронологическом порядке (в `_compute_elo` вдобавок висел пустой цикл
  `for m in reversed(matches): pass`). Все три показателя в промпте были
  мусором. Теперь матчи парсятся с датой и сортируются от новых к старым, Elo
  идёт строго вперёд по времени и стал игрой с нулевой суммой.
- `Atlético Madrid` был прописан в алиасах как `Ata. Madrid`, а в CSV он
  `Ath Madrid` — статистика по Атлетико не находилась никогда.
- CSV декодировался как UTF-8, хотя football-data.co.uk отдаёт cp1252: команды с
  диакритикой приходили битыми и не находились. Добавлен перебор кодировок.
- Пустой ответ сервера клался в кэш и залипал там на 12 часов.

**Матчи не находились**

- `fixtures.fetch` запрашивал только `status=SCHEDULED`, а ближайшие матчи у
  football-data.org почти всегда `TIMED` — `--auto` регулярно «не находил
  матчей» при полном календаре. Теперь берутся оба статуса, добавлены дедуп,
  отсечка слишком близких по времени матчей и понятные ошибки на 401/403/429.

**Падения на ровном месте**

- Отказ одной модели ронял весь матч: `list(ex.map(...))` пробрасывал исключение
  наружу. Слоты стали независимыми, есть `MIN_MODELS`.
- `resolve_models` падал с `TypeError`, если у модели в каталоге `created: null`.
- `_parse` брал первую пару `{}` в ответе — при рассуждении с примером JSON
  парсился пример, а не ответ. Теперь ищется последний сбалансированный объект.
- `PROMPT.format(**match)` ломался на лишних ключах матча (`home_flag`,
  `kickoff_utc`). Передаются только нужные поля.
- Любая осечка при загрузке флага (CDN недоступен, битый файл) валила матч
  целиком — теперь подставляется заглушка с названием команды.
- Нечисловое значение в `SEGMENTS`/`HOLD_SEC`/`FIXTURES_*` роняло процесс до
  первого запроса. Разбор вынесен в `config.py` с логом и дефолтом.
- `os.environ['OPENROUTER_API_KEY']` / `['FAL_KEY']` давали голый `KeyError` —
  заменены на понятные сообщения с подсказкой.
- Отсутствие ffmpeg обнаруживалось только на этапе склейки, уже после оплаченных
  запросов к моделям и fal. Проверка перенесена в начало.
- Ошибки ffmpeg терялись: `check=True` без перехвата stderr. Теперь текст ошибки
  попадает в исключение.

**Данные и артефакты**

- Слаг для нелатинских названий получался пустым: `out_dir` совпадал с корнем
  `out/`, архив назывался `.zip`, следующий матч затирал предыдущий.
- `predictions.json` и `.zip` писались на месте — автопостер мог подхватить
  недописанный архив. Запись стала атомарной (`.tmp` + `os.replace`).
- Промежуточные `_seg*.mp4` никогда не удалялись и копились в `out/`.
- Падение отправки превью в Telegram отменяло отправку самого кита.
- Подпись поста жёстко печатала «/5» независимо от числа ответивших моделей;
  версия для X могла превысить 280 символов.

**Мелочи качества**

- Кадры сегментов рендерились с общим `random.Random(seed)`, состояние которого
  зависело от числа уже нарисованных цифр — на стыке сегментов цифры чуть
  «прыгали». Теперь seed привязан к координате строки.
- `img.paste(tile, xy, tile)` для RGBA портил альфа-канал подложки; заменено на
  `alpha_composite`.
- Шрифты пересоздавались в цикле подбора кегля — добавлен `lru_cache`.
- Деление на ноль в `_procedural_wood` на однородной текстуре, падение на пустом
  списке строк, битый `TABLE_IMAGE` — закрыты.
- `Dockerfile`: `PYTHONUNBUFFERED=1` (логи Railway больше не теряются при
  падении), непривилегированный пользователь, `.dockerignore`.
