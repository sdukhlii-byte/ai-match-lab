# AI Match Lab — генератор видео «5 AI-моделей предсказывают счёт»

Матч → реальные прогнозы ChatGPT / Claude / Gemini / Perplexity / Grok →
видео, где рука маркером вписывает счёт в бланк → zip-кит → Telegram-группа →
автопостер `coinplay-predictions-to-social` публикует в Threads, Instagram (Reels) и X.

```
fixtures.py (football-data.org: ближайший реальный матч) ──► матч
            │
            ▼
         stats.py (football-data.co.uk: Elo, форма, H2H — только клубные лиги)
            │
            ▼
         predictions.py (OpenRouter, 5 моделей, веб-поиск + статистика в промпте)
            │
            ▼
         poster.py ──► blank.jpg (телефон с пустым табло на столе)
                   └─► filled.jpg (тот же бланк с цифрами «от руки»)
            │
            ▼
         video.py ──► first+last frame ──► рука дописывает цифры
            │          (по умолчанию Veo 3.1 Lite через OpenRouter — тот же
            │           ключ, что и для прогнозов, без отдельного FAL_KEY;
            │           fal.ai/kling25/veo31 — запасные, более дорогие варианты)
            ▼
         ffmpeg: склейка + стоп-кадр 2 сек ──► video.mp4
            │
            ▼
         kit.zip (kit.json + threads/ instagram/ x/) ──► Telegram ──► автопостер
```

Вспомогательный модуль `config.py` разбирает переменные окружения: опечатка
(`SEGMENTS=два`, `HOLD_SEC=2,5`) больше не роняет прогон, а логируется и
заменяется дефолтом.

## Реальная статистика в промпте

Перед запросом к моделям `stats.py` тянет бесплатные CSV с
[football-data.co.uk](https://www.football-data.co.uk) (без ключа, 22 европейские
лиги) и считает по ним:

- **Elo** обеих команд (свой расчёт по всей скачанной истории — CSV не даёт готового рейтинга);
- **форму** за последние 5 матчей (W/D/L, средние голы забитые/пропущенные);
- **личные встречи** (H2H) — сколько раз кто выигрывал, средняя результативность.

Эти цифры добавляются в промпт каждой модели строкой "Real stats: …", моделям
явно сказано ставить свежие новости (травмы, замена тренера) выше исторической
статистики, если они расходятся.

Лига определяется по полю `competition`: сравнение идёт по нормализованному
ключу (регистр, точки, дефисы и диакритика не важны), список — в
`stats.LEAGUE_CODES`. **Не работает** для сборных и турниров без клубного сезона
(Чемпионат мира, товарищеские, Лига чемпионов) и для эсенспорта/UFC — там просто
нет данных на football-data.co.uk, и генератор молча идёт дальше без блока статистики.

Имена клубов, которые в CSV пишутся иначе, чем обычно (`Man City`, `Man United`,
`Ath Madrid`, `Paris SG`), прописаны в `stats.ALIASES` — дополняй по мере
надобности. Если команда не найдена, в лог уходит подсказка с нормализованным
именем и примером того, как клубы называются в CSV.
`USE_STATS=false` — отключить совсем.

## Почему первый + последний кадр

Видео-модель, которой дали только пустой бланк, напишет **свои** цифры: не те,
что предсказали модели, и не те, что в подписи поста. Поэтому последний кадр
рендерится заранее с нашими цифрами, а модель только рисует между кадрами руку
с маркером. В конце ролика на бланке всегда правильный счёт.

## Запуск

```bash
pip install -r requirements.txt          # + ffmpeg в системе
export OPENROUTER_API_KEY=...  FAL_KEY=...
export TELEGRAM_BOT_TOKEN=...  TELEGRAM_CHAT_ID=-100...   # группа, которую читает автопостер

python generate.py --home Spain --away Argentina --home-flag es --away-flag ar \
    --competition "World Cup Final" --date 2026-07-19

python generate.py --match-file matches.json      # пачка матчей
python generate.py --auto                         # сам подберёт ближайшие матчи
```

Полезные флаги:
- `--no-video`: только кадры, промпт и кит с картинкой. Бесплатно, удобно проверить бланк.
- `--scores "1-2,2-1,2-2,1-0,2-1"`: свои счета без запросов к моделям (порядок ChatGPT, Claude, Gemini, Perplexity, Grok).
- `--no-send`: не отправлять в Telegram.
- `--keep-temp`: оставить промежуточные `_seg*.mp4` (по умолчанию удаляются).

Всё складывается в `out/<матч>/`: `blank.jpg`, `filled.jpg`, `prompt.txt`,
`predictions.json`, `video.mp4`, `<матч>.zip`.

Код возврата: `0` — все матчи собраны (или календарь пуст при `--auto`),
`1` — хотя бы один матч не собран. В конце прогона в лог уходит строка «Итог: …».

## Тесты

```bash
pip install -r requirements-dev.txt
python -m pytest -q          # 33 теста, без сети и без ключей
python -m pyflakes *.py
```

Тесты закрывают найденные баги регрессиями: порядок матчей в `stats`, разбор
ответа модели, фильтр статусов в `fixtures`, слаг для нелатинских названий,
детерминизм кадров между сегментами.

## Провайдеры видео и цена ролика

`VIDEO_PROVIDER` выбирает, кто рендерит сегмент. Два семейства значений:

| Значение | API | Нужен ключ | Цена за сегмент* |
|---|---|---|---|
| `or-seedance-fast` (по умолчанию) | OpenRouter | `OPENROUTER_API_KEY` (тот же, что для прогнозов) | 4 сек × `$0.04`/сек ≈ **$0.16**/сегмент |
| `or-veo31lite` | OpenRouter | `OPENROUTER_API_KEY` | `OR_VIDEO_DURATION` (по умолчанию 4) сек × `$0.03`/сек (720p, без звука) ≈ **$0.12**/сегмент — дешевле всех, но на реальных роликах хуже всех держал текст: плыл уже на первом кадре, проценты расползались по экрану (в заголовок, в статус-бар, в иконки), а клетка со счётом однажды превратилась в сплошную заливку без цифры. Не рекомендуем, если не готовы мириться с браком |
| `or-seedance-mini` | OpenRouter | `OPENROUTER_API_KEY` | 4 сек × `$0.034`/сек ≈ **$0.13**/сегмент, но модель меньше — может просесть качество |
| `kling25` | fal.ai | отдельный `FAL_KEY` | 10 сек ≈ **$0.70**/сегмент — самый надёжный по опыту прошлых генераций, но заметно дороже |
| `veo31` | fal.ai | отдельный `FAL_KEY` | 8 сек × `$0.40`/сек (1080p, со звуком) ≈ **$3.2**/сегмент |

\* За ролик цену умножь на число сегментов, которое даёт `SEGMENTS`
(по умолчанию — одна строка/2 клетки на сегмент, в обоих стилях).
При 5 моделях и `PREFILL_ROWS=1` (первая строка уже готова на старте) —
4 сегмента: `or-seedance-fast` × **$0.16** ≈ **$0.64 за ролик**, с запасом
укладывается в бюджет до $1. Если и `seedance-fast` не вытянет мелкий
текст на реальной генерации — следующий шаг попробовать `kling25`
(дороже примерно в 4 раза, но именно под него написаны все текущие
анти-галлюцинационные формулировки промпта).

Раньше `cyber` паковал по 2 строки в один сегмент — короче и дешевле
(**$0.36**), но на реальной генерации это ломалось: модели не хватало
«воздуха» на 4 клетки за один непрерывный план, и она путала элементы —
цифры наплывали на гербы команд, подписи двоились и плыли. Сегмент на
строку — тот же принцип, что раньше защищал `marker`-стиль (там руке нужно
физически успеть коснуться каждой клетки), просто выяснилось, что и `cyber`
без рук страдает от того же переусложнения кадра, если сразу двигать
слишком много.
`SEGMENTS=1` вернёт старую схему (один ролик на весь прогноз, ≈$0.12–0.24) —
дешевле, но с более высоким риском путаницы на всех клетках сразу.

`or-*` идут через OpenRouter (openrouter.ai/docs/guides/overview/multimodal/video-generation)
— отдельный `FAL_KEY` для них не нужен, подходит уже существующий
`OPENROUTER_API_KEY`. `kling25`/`veo31` — через fal.ai, это отдельный сервис
и отдельный ключ (`FAL_KEY`); держим их как запасной вариант, если качество
`or-*` не устроит.

## Автоматический подбор реальных матчей (`--auto`)

`Dockerfile` по умолчанию запускает `python generate.py --auto` — генератор сам
находит ближайшие реальные (ещё не сыгранные) матчи топ-лиг через бесплатный API
[football-data.org](https://www.football-data.org):

1. Зарегистрируйся (2 минуты, без карты): https://www.football-data.org/client/register
2. Добавь в переменные Railway: `FOOTBALL_DATA_API_KEY=<ключ из письма>`.
3. Готово — при каждом запуске берутся ближайшие по времени запланированные матчи
   из `FIXTURES_COMPETITIONS` в окне `FIXTURES_DAYS_AHEAD` дней.

Матчи со статусами `SCHEDULED` и `TIMED` считаются одинаково подходящими: у
football-data.org ближайшие игры почти всегда `TIMED`, и фильтр только по
`SCHEDULED` прятал как раз то, что нужно.

Если в окне вообще нет подходящих матчей (пауза в календаре, международное окно,
межсезонье) — это не ошибка: процесс тихо завершается с кодом 0 и предупреждением
в логе, а не падает. Так Railway не уходит в рестарт-луп.

В `FIXTURES_COMPETITIONS` по умолчанию — весь клубный список бесплатного тарифа
football-data.org (10 лиг). Особенно важна **BSA** (бразильская Серия A): у Южной
Америки своё, отдельное от УЕФА международное окно (CONMEBOL), которое почти
никогда не совпадает с европейским — когда все топ-лиги Европы разом встают на
паузу на 10+ дней (например, отборочные к Евро), Бразилейран обычно продолжает
играть, и `--auto` всё равно находит свежий матч.

`matches.json` + `--match-file` никуда не делись — это ручной/тестовый режим.

### Чтобы каждый день приходило новое видео

`--auto` при каждом запуске просто берёт САМЫЙ БЛИЖАЙШИЙ ещё не сыгранный матч.
Отсюда два момента, которые нужно настроить отдельно:

**1. Railway должен запускать контейнер РАЗ В ДЕНЬ, а не постоянно.**
`generate.py --auto` — это одноразовый скрипт (сходил, собрал видео, отправил,
завершился), а не вечный процесс. Обычный Railway-сервис после выхода из
контейнера либо перезапустит его сразу же (если Restart Policy = `Always` —
получится спам по несколько видео в день), либо будет пытаться и падать в
рестарт-луп. Правильный способ — **Railway Cron Schedule**:
1. Открой сервис -> **Settings -> Cron Schedule**.
2. Впиши, например, `0 9 * * *` (каждый день в 09:00 **UTC** — переведи на своё
   время, Railway крон работает в UTC).
3. Railway сам запустит контейнер по расписанию, дождётся выхода (`sys.exit`)
   и не будет перезапускать его до следующего срабатывания.

**2. Дедупликация — чтобы не прислать один и тот же матч два дня подряд.**
Если ближайший найденный матч ещё не сыгран к следующему крону (например, до
него было 3 дня), без доп. защиты `--auto` нашёл бы ЕГО ЖЕ и на следующий
день. Поэтому теперь после каждой успешной отправки матч запоминается в
`state.py` (файл `POSTED_STATE_FILE`, по умолчанию `state/posted.json`) и
больше не выбирается, пока не истечёт 60 дней. Чтобы это переживало между
отдельными крон-запусками (а не сбрасывалось при каждом старте контейнера),
**нужен Railway Volume**:
1. Сервис -> **Settings -> Volumes -> New Volume**.
2. Mount path: `/app/state`.
3. Готово — файл дедупликации теперь на постоянном диске, а не в эфемерном
   контейнере.

Без тома всё равно будет работать, просто дедупликация обнулится при
следующем деплое (переменные окружения при этом не теряются — теряется
только сам файл `posted.json`). Отключить дедупликацию полностью:
`FIXTURES_SKIP_POSTED=false`.

### Почему постоянно одна и та же лига

Дедупликация выше не даёт прислать ОДИН И ТОТ ЖЕ матч дважды — но не мешает
каждый день присылать матч из ОДНОЙ И ТОЙ ЖЕ лиги, просто разный. Причина:
`--auto` берёт самый ближайший по времени матч среди ВСЕХ лиг разом, а у
лиги с плотным календарём (например, Série A Бразилии — там игры почти
каждый день) на любой момент банально больше кандидатов на роль «самый
ближайший», чем у лиги, которая играет раз в выходные. Со временем это
статистически всегда перетягивает выбор на себя.

Начиная с этой версии `fixtures.fetch()` при выборе исключает турниры из
последних `FIXTURES_AVOID_LAST_COMPETITIONS` публикаций (по умолчанию `2`),
если это оставляет хоть какую-то альтернативу — то есть не блокирует
публикацию, если сейчас реально играет только одна лига. Ротация читает
историю турниров из того же `POSTED_STATE_FILE`, так что тоже требует тома,
как и обычная дедупликация. `FIXTURES_AVOID_LAST_COMPETITIONS=0` возвращает
старое поведение (просто самый ближайший матч).

## Дата матча

Дата обязательно должна быть в будущем (`YYYY-MM-DD`). Прошедшая дата означает,
что у матча уже есть реальный результат — модели этого не знают и просто
нафантазируют правдоподобный «прогноз», поэтому такой матч **отклоняется ещё до
похода к API моделей** (деньги не тратятся).
Отключить проверку: `ALLOW_PAST_DATES=true`.

## Фон (`assets/table.jpg`)

Карточка занимает 72% ширины кадра (`poster.compose_frame`), остальное —
подложка из `TABLE_IMAGE`. Размер — **1080×1920**, лишнее обрезается по центру.

Важно: центр подложки почти целиком перекрыт телефоном, поэтому вся фактура
должна жить по краям — сверху, снизу и по бокам. Центр лучше держать тёмным
и спокойным, иначе он будет спорить с экраном.

Промпт для генерации фона (Midjourney / DALL·E / Flux), под кибер-стиль ролика:

```
Top-down view of a dark luxury desk surface, 9:16 vertical, photorealistic.
Black brushed metal and smoked glass with subtle violet and gold rim light.
Scattered around the EDGES of the frame only: a few gold bitcoin coins,
a sleek black smartphone showing a glowing green candlestick chart,
thin neon violet light streaks, faint holographic data particles in the air.
The CENTER of the frame is empty, clean, dark and uncluttered — nothing there.
Moody cinematic lighting, deep blacks, high contrast, expensive fintech mood,
shallow depth of field, no text, no logos, no people, no hands.
```

Готовую картинку положить в `assets/table.jpg` (или указать свой путь в
`TABLE_IMAGE`). Если файла нет — рисуется процедурное дерево, как раньше.

## Как сделать ближе к референсу

1. **Иконки моделей.** `assets/icons/chatgpt.png`, `claude.png`, `gemini.png`,
   `perplexity.png`, `grok.png` (PNG с прозрачностью). Если файла нет, рисуется нейтральный значок.
2. **Эмблемы клубов** для клубных матчей: `assets/crests/<club>.png` или URL в
   `home_flag` / `away_flag`. Флаги стран подтягиваются сами по ISO-коду (`es`, `ar`, `gb-eng`).
3. **Длина.** По умолчанию (5 моделей, `PREFILL_ROWS=1` → 4 сегмента ×
   `OR_VIDEO_DURATION=4` + `HOLD_SEC=2`) — ≈18 сек. Короче ценой надёжности:
   `SEGMENTS=2` или `3` пакует несколько строк в один клип — дешевле и
   быстрее, но так и ловили баг «цифры наплывают на гербы» (см. выше), так
   что после `SEGMENTS<остаток строк` смотри реальную генерацию внимательно.
4. **Музыка.** Положи трек в `assets/` и укажи `MUSIC_FILE=assets/beat.mp3`;
   громкость — `MUSIC_VOLUME` (по умолчанию `0.25`), сдвиг по треку —
   `MUSIC_OFFSET` (сек, по умолчанию `0`) — чтобы подвести пик/дроп трека
   ровно под момент раскрытия вердикта. Трек зацикливается под
   всю длину ролика автоматически.

## Оформление (стиль «криптоказино»)

Прогноз показывается **на экране смартфона**, лежащего на тёмном столе, а не
на печатном листе. Так неоновое свечение цифр физически оправдано: из бумаги
свет не идёт, из экрана — идёт. `poster.py` рисует сам экран
(`PAPER_W × PAPER_H` = 1240×2684, пропорции телефона), `compose_frame()`
собирает вокруг него корпус и ставит устройство в сцену.

- **Цвета**: корпус почти чёрный `#07060C`→`#140F22`, все рамки и обводки —
  золото `#E6B54A`, счёт и неон цифр `#FFD65C`, фиолет `#7C58F0` остался
  только как фирменный подсвет (разделители, свечения).
- **Цифры**: `ChakraPetch-Bold`, строго по центру клетки, свечение в три слоя
  (широкая засветка → плотный ореол → светлое ядро). При `VIDEO_STYLE=marker`
  вместо них рисуется прежний рукописный `Kalam-Bold`.
- **Шрифт**: Roboto Condensed (Bold — заголовок, SemiBold — подписи и имена моделей).
- **Лого**: `assets/logo/mark.png`; если файла нет, рисуется приблизительная версия.
- Старые константы (`NAVY`, `LIME`, `CYAN`, `PAPER`) оставлены как алиасы новых цветов.

### Что показывает экран

Сверху вниз: строка состояния телефона (часы, связь, батарея, «дырка»
фронталки), компактная шапка со знаком Coinplay, крупный хук **WHO WINS?**,
подзаголовок, лига и дата матча, эмблемы команд **с названиями** (по гербу не
всегда понятно, кто играет), полоса `AI ANALYSIS` с процентом, таблица
моделей, плашка `AI CONSENSUS` с силой согласия и нижняя строка `LINK IN BIO`
с пометкой 18+.

Коэффициентов на экране нет намеренно: своего источника кф у проекта нет, а
выдумывать их в iGaming-креативе нельзя. Аргументом служит то, что мы
действительно посчитали, — единодушие моделей («4 OF 5 MODELS AGREE»).

Лига, дата и консенсус берутся из тех же данных, что и подпись поста
(`generate.consensus_text()` использует тот же `_verdict()`), поэтому экран и
текст поста не могут разойтись.

### Как показано, что ИИ «считает»

Ролик должен читаться как работа, а не как готовая табличка, поэтому между
первым и последним кадром меняются три вещи, и все три — только яркостью
уже существующих элементов:

1. полоса `AI ANALYSIS` растёт (0% → 100%) ровно по числу ответивших моделей;
2. строка модели загорается (имя из серого в белое, рамки клеток — в золото)
   в тот момент, когда её счёт появился;
3. плашка `AI CONSENSUS` внизу до финала почти неразличима (цвет `HIDDEN`),
   а когда ответили все — загорается золотом со свечением.

Почему именно яркостью: геометрия и глифы на всех кадрах одинаковы, а текст,
которого на опорном кадре нет, генеративная модель дорисовывает с искажениями.

### Как телефон вписывается в сцену

Плоский прямоугольник поверх фотографии всегда читается как наклейка, поэтому
`compose_frame()` делает четыре вещи: лёгкую перспективу (верх уже низа),
перенос светотени фона на **корпус** (экран не гасим — он источник света),
зерно под шум фотографии и двухслойную тень (плотная контактная + широкая
мягкая). Плюс `_screen_spill()` подсвечивает стол вокруг телефона — именно
эта засветка читается как «экран включён».

## Подпись поста

Генерируется из прогнозов: счета всех ответивших моделей, консенсус, самый частый
счёт и призыв «Link in bio». Для X своя версия, гарантированно до 280 символов.

## Деплой (Railway)

`Dockerfile` ставит ffmpeg и cairo, запускает контейнер от непривилегированного
пользователя и не буферизует логи. Сервис работает как cron-job
(`python generate.py --auto`).

## Что было исправлено

**Критично — статистика считалась неправильно**

- `stats._load_matches` разворачивал список дважды (`matches.reverse()` +
  `return list(reversed(matches))`), то есть не делал ничего, и матчи вообще
  никогда не сортировались по дате — сезоны просто склеивались подряд. В итоге
  «форма за последние 5 матчей» брала **первые** матчи сезона, а Elo считался в
  обратном хронологическом порядке (в `_compute_elo` вдобавок висел пустой цикл
  `for m in reversed(matches): pass`). Все три показателя в промпте были
  мусором. Теперь матчи парсятся с датой и сортируются от новых к старым, Elo
  идёт строго вперёд по времени и стал игрой с нулевой суммой.
- `Atlético Madrid` был прописан в алиасах как `Ata. Madrid`, а в CSV он
  `Ath Madrid` — статистика по Атлетико не находилась никогда.
- CSV декодировался как UTF-8, хотя football-data.co.uk отдаёт cp1252: команды с
  диакритикой приходили битыми и не находились. Добавлен перебор кодировок.
- Пустой ответ сервера клался в кэш и залипал там на 12 часов.

**Матчи не находились**

- `fixtures.fetch` запрашивал только `status=SCHEDULED`, а ближайшие матчи у
  football-data.org почти всегда `TIMED` — `--auto` регулярно «не находил
  матчей» при полном календаре. Теперь берутся оба статуса, добавлены дедуп,
  отсечка слишком близких по времени матчей и понятные ошибки на 401/403/429.

**Падения на ровном месте**

- Отказ одной модели ронял весь матч: `list(ex.map(...))` пробрасывал исключение
  наружу. Слоты стали независимыми, есть `MIN_MODELS`.
- `resolve_models` падал с `TypeError`, если у модели в каталоге `created: null`.
- `_parse` брал первую пару `{}` в ответе — при рассуждении с примером JSON
  парсился пример, а не ответ. Теперь ищется последний сбалансированный объект.
- `PROMPT.format(**match)` ломался на лишних ключах матча (`home_flag`,
  `kickoff_utc`). Передаются только нужные поля.
- Любая осечка при загрузке флага (CDN недоступен, битый файл) валила матч
  целиком — теперь подставляется заглушка с названием команды.
- Нечисловое значение в `SEGMENTS`/`HOLD_SEC`/`FIXTURES_*` роняло процесс до
  первого запроса. Разбор вынесен в `config.py` с логом и дефолтом.
- `os.environ['OPENROUTER_API_KEY']` / `['FAL_KEY']` давали голый `KeyError` —
  заменены на понятные сообщения с подсказкой.
- Отсутствие ffmpeg обнаруживалось только на этапе склейки, уже после оплаченных
  запросов к моделям и fal. Проверка перенесена в начало.
- Ошибки ffmpeg терялись: `check=True` без перехвата stderr. Теперь текст ошибки
  попадает в исключение.

**Данные и артефакты**

- Слаг для нелатинских названий получался пустым: `out_dir` совпадал с корнем
  `out/`, архив назывался `.zip`, следующий матч затирал предыдущий.
- `predictions.json` и `.zip` писались на месте — автопостер мог подхватить
  недописанный архив. Запись стала атомарной (`.tmp` + `os.replace`).
- Промежуточные `_seg*.mp4` никогда не удалялись и копились в `out/`.
- Падение отправки превью в Telegram отменяло отправку самого кита.
- Подпись поста жёстко печатала «/5» независимо от числа ответивших моделей;

**Мелочи качества**

- Кадры сегментов рендерились с общим `random.Random(seed)`, состояние которого
  зависело от числа уже нарисованных цифр — на стыке сегментов цифры чуть

- `img.paste(tile, xy, tile)` для RGBA портил альфа-канал подложки; заменено на

- Шрифты пересоздавались в цикле подбора кегля — добавлен `lru_cache`.
- Деление на ноль в `_procedural_wood` на однородной текстуре, падение на пустом
  списке строк, битый `TABLE_IMAGE` — закрыты.
- `Dockerfile`: `PYTHONUNBUFFERED=1` (логи Railway больше не теряются при
  падении), непривилегированный пользователь, `.dockerignore`.
